# Knowledge Dungeon Engine 0.1.0

**Release date:** 2026-11-23 (package version; no Git tag or published release exists)

## Summary

The first packaged release of the headless Knowledge Dungeon gameplay engine. It extracts subject graphs, note validation, progression, review scheduling, fishing, village and dungeon navigation, study sessions, statistics, and learner assistance into a renderer-neutral TypeScript library. A host supplies the interface, input, and durable storage.

The package is private and no Git tag or npm release has been published. This note documents the `0.1.0` package state in the repository.

## Highlights

- **Headless facade:** `KnowledgeDungeonEngine` opens a versioned state, serializes commands, emits cloned snapshots, and exposes gameplay commands through dispatch methods and named entry points.
- **Learning loop:** create a subject, map topics, write and validate notes, generate artifacts, clear rooms, and collect rewards.
- **Review:** per-room SM-2 scheduling with explicit 0–5 recall ratings and durable save/resume/discard for interrupted reviews.
- **Fishing:** a pure, seeded state machine plus an explicit-context command layer with recall-dependent rewards.
- **Progression safety:** award-once ledgers for room clears, review passes, and fishing catches, stored atomically with their rewards.
- **World models:** deterministic grid dungeon layout, floor visibility, collision, room travel, teleport cooldown, village movement, NPCs, and interaction selection.
- **Study records:** sessions that count unique room visits and recover at their last activity.
- **Host independence:** no React, Pixi, Phaser, Electron, DOM, or network dependency in the engine.

## Compatibility and Prerequisites

- **Node.js:** 20 or newer to build and test.
- **Runtime:** ES2022 with `structuredClone`, `Blob`, and `crypto.randomUUID()` (or injected factories).
- **Module format:** ESM; types are published at `dist/index.d.ts`.
- **Package status:** private; not published to npm.
- **State compatibility:** `EngineState` version `1`. Existing Knowledge Dungeon browser saves and backup files are **not compatible**; this release includes no migration.
- **Storage:** `MemoryEngineStorage` is volatile. Durable operation requires a host `EngineStorage` adapter.

## Installation or Upgrade

Install from Git:

```sh
npm install github:McFuzzySquirrel/knowledge-dungeon-engine
```

For a reproducible deployment, pin a commit:

```sh
npm install github:McFuzzySquirrel/knowledge-dungeon-engine#<commit-sha>
```

Verify a local checkout:

```sh
npm install
npm test
npm run typecheck
npm run build
```

This is the initial release, so there is no upgrade path from an earlier version of this package. For hosts replacing an older Knowledge Dungeon build, plan a separate migration; the engine will not load an old save.

## Known Limitations

- **No user interface.** Rendering, input, audio, camera, layout, and accessibility are host responsibilities.
- **No durable adapter or migration.** Only `MemoryEngineStorage` ships; no browser or Node persistence adapter is included.
- **No platformer movement.** Dungeon movement is grid-based and does not implement gravity or jumping.
- **No anti-cheat boundary.** Fishing commands trust the host's state-machine results.
- **No npm publication.** Installation is from the Git repository.
- **No network or sync.** The engine is local-only; multi-device sync and accounts are host features.
- **Test coverage is partial by module.** The suite covers core domains, commands, storage, and world mechanics; the statistics and assistance modules are implemented but do not have dedicated tests in this repository.
- **No CI workflow is published**, so validation is local rather than enforced by a repository workflow.

## Security and Privacy

- The engine performs no network requests, telemetry, or analytics.
- No credentials, tokens, signing keys, or private URLs are included.
- Learner note text and artifact text live in host-persisted state; the host owns encryption, access control, retention, and deletion.
- Reward ledgers and assistance inputs use app-minted ids, counts, and enum codes rather than learner prose.
- Attachment bytes are stored in state and never uploaded by the engine; external attachment URLs are recorded, not fetched.
- Report security concerns through the repository's GitHub issue tracker without including learner data or secrets.
